# Debug Session: adapter-fn-not-a-function

## Current Focus

- **hypothesis**: Next.js 16 expects a default or named proxy export structure that is not being compiled or resolved correctly under Turbopack, resulting in an empty or improperly resolved middleware module.
- **next_action**: "Inspect the compiled middleware output or test running the dev server without Turbopack to see if adapterFn is resolved correctly."

## Evidence

- *2026-06-28 09:22*: Found that `.next/dev/server/middleware.js` generated by the dev server has a size of 0 bytes, indicating compilation failure or mismatch in Turbopack.
- *2026-06-28 09:55*: Verified that production build (`next build` / `next start`) runs the middleware without any issues.
- *2026-06-28 09:56*: Running `next dev --webpack` completely resolves the compilation bug and runs request interception successfully in development mode.

## Eliminated

- **Edge Runtime compilation**: Not applicable as Proxy files in Next.js 16 default to Node.js runtime and cannot be configured to run on Edge.
