# Requirements: Document RAG REST API (v1.1)

**Defined:** 2026-06-18
**Core Value:** Standardize retrieval and generation workflows to modern LangChain Expression Language (LCEL) and ensure clean, unified code standards.

## v1.1 Requirements

### LangChain Expression Language (LCEL)

- [x] **LCEL-01**: Refactor the generative Q&A answering pipeline to construct a declarative LCEL chain (e.g. `context | prompt | llm | output_parser`).
- [x] **LCEL-02**: Standardize model prompt templates utilizing `ChatPromptTemplate` and replace custom text extraction with `StrOutputParser`.

### Native Retrievers (RET)

- [x] **RET-01**: Expose the persistent Chroma vector store as a native LangChain `Retriever` component (`vectorstore.as_retriever()`) rather than invoking custom list-similarity search functions.

### Code Quality & Standards (CLEAN)

- [x] **CLEAN-01**: Standardize all backend imports to use clean absolute module imports (e.g. `from app.*`).
- [x] **CLEAN-02**: Unify API error boundaries, ensuring all custom domain exceptions (e.g. `DocumentIngestionError`, `VectorStoreError`, `InferenceError`) map cleanly to FastAPI `HTTPException` status codes without leaking internal stack traces.
- [x] **CLEAN-03**: Enforce PEP8 styling, double-quoted string conventions, and maintain clean passing integration tests with pytest.

---

## Out of Scope

- **Web Frontend Dashboard**: The scope is strictly a backend REST API with endpoints designed for programmatic access.
- **Persistent User Accounts**: Authentication, user accounts, and multi-tenant session storage are excluded.
- **Cloud Vector Store Hosting**: Storing embeddings in Pinecone/Milvus cloud services is excluded; all database storage remains on the local filesystem.
