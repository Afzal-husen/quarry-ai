# Roadmap: Document RAG REST API

## Overview

This roadmap details the progressive phases to construct a fully functional backend REST API for document Q&A Retrieval-Augmented Generation (RAG). Sliced using **Vertical MVP** methodology, each phase delivers a tangible, testable capability.

## Phases

- [x] **Phase 1: Environment & FastAPI Bootstrap** - Setup Python 3.14 virtual environment and verify running skeleton server.
- [x] **Phase 2: Document Ingestion Engine** - Build multi-format document parser and text chunking logic with file upload route.
- [x] **Phase 3: Local Vector Storage & Embedding Index** - Generate text embeddings and persist/query local Chroma/FAISS database.
- [x] **Phase 4: Generative Q&A Inference** - Configure LangChain Groq model connection and contextual Q&A prompt.
- [x] **Phase 5: Q&A API Integration & Verification** - Expose E2E programmatic endpoint `/query` and execute verification. (completed 2026-06-18)

## Phase Details

### Phase 1: Environment & FastAPI Bootstrap

**Goal**: Set up virtual environment and verify a basic running FastAPI web server.
**Mode**: mvp
**Depends on**: Nothing
**Requirements**: ENV-01, ENV-02, API-01
**Success Criteria** (what must be TRUE):

  1. FastAPI server starts successfully on the local port.
  2. Swagger OpenAPI auto-documentation is fully interactive at `/docs`.
  3. Groq API keys and configurations load securely from the local `.env` or system environment.

**Plans**: 1 plan

Plans:

- [x] 01-01: Setup Python 3.14 workspace, install FastAPI/uv dependencies, and build entry point routes.

### Phase 2: Document Ingestion Engine

**Goal**: Process and extract text from uploaded PDF/DOC/DOCX files.
**Mode**: mvp
**Depends on**: Phase 1
**Requirements**: API-02, INGEST-01, INGEST-02, INGEST-03
**Success Criteria** (what must be TRUE):

  1. REST endpoint `/upload` accepts a PDF or DOCX file.
  2. Uploaded documents are parsed into structured clean text using LangChain document loaders.
  3. Extracted text is successfully split into character chunks and stamped with document UUID.

**Plans**: 2 plans

Plans:

- [x] 02-01: Implement document parsing pipelines for PDF/DOCX using LangChain loaders.
- [x] 02-02: Implement document text chunking processor and `/upload` endpoint.

### Phase 3: Local Vector Storage & Embedding Index

**Goal**: Embed and index chunked text into a local vector database.
**Mode**: mvp
**Depends on**: Phase 2
**Requirements**: EMBED-01, EMBED-02, EMBED-03
**Success Criteria** (what must be TRUE):

  1. Extracted chunks are converted to vectors using local Hugging Face embeddings.
  2. Embeddings database (Chroma or FAISS) successfully persists index to disk.
  3. Querying the index returns the top-K semantically relevant text chunks.

**Plans**: 1 plan

Plans:

- [x] 03-01: Set up Hugging Face embeddings and persist Chroma/FAISS vector database to disk.

### Phase 4: Generative Q&A Inference

**Goal**: Construct retrieval prompts and generate grounding responses via Groq LLM inference.
**Mode**: mvp
**Depends on**: Phase 3
**Requirements**: GEN-01, GEN-02
**Success Criteria** (what must be TRUE):

  1. Connection to Groq model (`llama-3.1-70b` or `mixtral-8x7b`) is established via LangChain.
  2. LLM constructs a response based strictly on the retrieved context chunks.

**Plans**: 1 plan

Plans:

- [x] 04-01: Set up LangChain Groq model connection and Q&A inference pipeline.

### Phase 5: Q&A API Integration & Verification

**Goal**: Wire retrieval and generation into the final programmatic `/query` REST endpoint and verify.
**Mode**: mvp
**Depends on**: Phase 4
**Requirements**: API-03
**Success Criteria** (what must be TRUE):

  1. Endpoint `/query` accepts query strings, fetches context from local database, performs Groq generation, and returns a JSON answer with source text snippets.
  2. End-to-end RAG upload-to-Q&A flows are verified successfully.

**Plans**: 2 plans

Plans:

- [ ] 05-01: Wire end-to-end Q&A retrieval and generation into FastAPI `/query` endpoint.
- [ ] 05-02: Create integration test scripts to verify the complete ingestion and Q&A flow.
