# Requirements: Document RAG REST API

**Defined:** 2026-05-31
**Core Value:** Enable seamless, low-latency document parsing and precise Q&A retrieval via a programmatic REST API using local embeddings and high-speed cloud LLM inference.

## v1 Requirements

### Environment & Server Setup (ENV)

- [ ] **ENV-01**: Setup Python 3.14 virtual environment with dependencies managed by `uv`.
- [ ] **ENV-02**: Secure environment variable loading for API keys (e.g. `GROQ_API_KEY`).

### API Endpoints (API)

- [ ] **API-01**: FastAPI REST API skeleton boots up and serves standard OpenAPI auto-documentation at `/docs`.
- [ ] **API-02**: Endpoint `/upload` accepts PDF, DOC, or DOCX files and returns a unique document identifier (UUID) upon successful parsing.
- [x] **API-03**: Endpoint `/query` accepts a document ID and question string, and returns the generated answer alongside relevant source snippet citations.

### Document Ingestion (INGEST)

- [ ] **INGEST-01**: Extract text content from PDF files cleanly using LangChain document loaders (e.g. `PyPDFLoader`).
- [ ] **INGEST-02**: Extract text content from DOC/DOCX files cleanly using LangChain document loaders (e.g. `Docx2txtLoader`).
- [ ] **INGEST-03**: Chunk extracted document text using a recursive character splitter (e.g. `RecursiveCharacterTextSplitter`) with configurable chunk sizes and overlaps.

### Vector Storage & Embedding (EMBED)

- [ ] **EMBED-01**: Initialize and configure local Hugging Face embedding model (e.g., `sentence-transformers/all-MiniLM-L6-v2`) via LangChain.
- [ ] **EMBED-02**: Index generated embedding vectors into a local vector database (Chroma or FAISS) persisting to disk.
- [ ] **EMBED-03**: Retrieve the top-K most relevant text chunks from the vector database matching a semantic user query.

### Generative Answering (GEN)

- [ ] **GEN-01**: Connect generative pipeline to the Groq API model (e.g., `llama-3.1-70b` or `mixtral-8x7b`) via LangChain's Groq integration.
- [ ] **GEN-02**: Implement a system prompt template that binds retrieved context and user query, ensuring answers are strictly grounded in retrieved document chunks.

## v2 Requirements

### Analytics & History (HIST)

- **HIST-01**: Endpoint `/history` to fetch logs of past questions and generated answers.
- **HIST-02**: Store query history and performance metrics in local SQLite database.

### Enhanced Ingestion (ENH)

- **ENH-01**: Support OCR for scanned PDF files.
- **ENH-02**: Enable multiple file selection to index folders or bulk document uploads.
