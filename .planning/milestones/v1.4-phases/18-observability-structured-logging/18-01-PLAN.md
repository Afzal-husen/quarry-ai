# Plan 18-01: Observability & Structured Logging

## Goal

Emit structured JSON log lines for all HTTP requests and errors. Instrument the query pipeline to capture per-phase latency (retrieval, reranking, LLM generation). Include full tracebacks on error.

## Requirements Addressed

- **OBS-01**: All requests emit structured JSON log entries (method, path, status, duration, user_id).
- **OBS-02**: Query latency is broken down by phase: retrieval, reranking, and LLM generation.
- **OBS-03**: Error logs include full exception tracebacks with contextual metadata.

## Success Criteria

1. Every HTTP request outputs a single-line structured JSON record on stdout containing `method`, `path`, `status_code`, `duration_ms`, `user_id`, and `client_ip`.
2. Logging for `/query` and `/query/stream` includes a `latency_breakdown` field: `{"retrieval_ms": X, "reranking_ms": Y, "generation_ms": Z, "total_ms": W}`.
3. Unhandled server exceptions (500) print a structured JSON log containing the full traceback string and request metadata (method, path, user_id).
4. All application and Uvicorn server logs use standard JSON formatting on stdout.
5. All automated tests in the test suite pass successfully.
