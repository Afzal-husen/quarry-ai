# Phase 16: Streaming LLM Responses - Context

**Gathered:** 2026-06-24
**Status:** Ready for planning

<domain>
## Phase Boundary

Expose a streaming Q&A endpoint that returns generative answers token-by-token via Server-Sent Events (SSE). Keep the API responsive, using the same multi-document hybrid retrieval, deduplication, and FlashRank reranking pipeline before generative answering starts. Include source citations in the initial event payload.

</domain>

<decisions>
## Implementation Decisions

### Endpoint URL & Schema
- **D-01 (Route Path):** Add a new endpoint `POST /query/stream` in `backend/app/routes/query.py` that accepts the exact same `QueryRequest` schema as `/query`.
- **D-02 (Authentication & Ownership):** Apply the same JWT authentication dependencies and all-or-nothing document ownership checks (404 if vectorstore missing, 403 if user doesn't own document) as the standard `/query` endpoint. Ensure all checks run synchronously before starting the stream.

### Retrieval & Reranking
- **D-03 (Pipeline Integration):** Execute the complete hybrid retrieval, exact-text deduplication, and FlashRank reranking pipeline to yield `matching_chunks` *before* initiating the SSE generator stream.

### SSE Stream Protocol
- **D-04 (Content Type):** Return a FastAPI `StreamingResponse` with `media_type="text/event-stream"`.
- **D-05 (Event Structure):**
  - **First event:** Send the citation metadata list under a `"citations"` key. Format:
    ```
    data: {"citations": [{"source_filename": "...", "page_index": ..., "document_id": "...", "text": "..."}]}
    
    ```
  - **Intermediate events:** Yield individual token chunks as they are generated by the LLM. Format:
    ```
    data: {"token": "chunk_text"}
    
    ```
  - **Final event:** Send a literal done signal to indicate stream completion. Format:
    ```
    data: [DONE]
    
    ```
- **D-06 (Streaming Generator):** Implement `QAPipeline.generate_answer_stream()` returning an async generator that yields individual text tokens. Leverage LangChain's `.astream()` Runnable sequence.

### Error Handling
- **D-07 (Mid-stream Errors):** If an error occurs during LLM token streaming (e.g., Groq connection drop, API rate limits, or context length exceeded), yield a final structured error message:
  ```
  data: {"error": "Error details..."}
  
  ```
  Then exit the generator to close the connection.

</decisions>

## Existing Code Insights

### Reusable Assets
- `QAPipeline.generate_answer()`: Formats system prompts and document contexts. The system prompts structure and grounding constraints should remain identical.
- `ChatGroq`: Under the hood, LangChain's ChatGroq wrapper supports `astream()`.

### Established Patterns
- **Access Control:** The route handler in `query.py` iterates over resolved document IDs to check disk presence and directory ownership.
- **Exception Mapping:** standard exceptions from the QA pipeline (like `GroqConnectionError`, `InferenceError`) are caught and wrapped.

### Integration Points
- `/query/stream` in `backend/app/routes/query.py` will use `StreamingResponse`.
- `QAPipeline` in `backend/app/core/qa.py` needs a new method `generate_answer_stream()` returning an async generator of string tokens.
