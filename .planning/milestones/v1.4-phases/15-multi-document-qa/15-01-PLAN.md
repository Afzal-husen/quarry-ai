# Plan 15-01: Extend /query for multi-document retrieval, deduplication, and enriched citations

## Goal
Extend the `POST /query` endpoint to accept an optional `document_ids` list in addition to the existing `document_id` field. Run hybrid retrieval per-document, pool and deduplicate chunks, rerank, and pass the final set to the LLM. Extend citation output to include `document_id` per chunk.

<threat_model>
- **Threat**: Path traversal via user-supplied document IDs.
- **Mitigation**: Each string in `document_ids` is validated as a UUID using the same `uuid.UUID()` check already applied to `document_id`.
- **Threat**: Cross-tenant data leakage by querying another user's document in the multi-doc list.
- **Mitigation**: All-or-nothing ownership check — if any requested ID does not exist in the current user's vectorstore directory, the request fails with 403/404 before any retrieval runs.
</threat_model>

<action>
In `backend/app/routes/query.py`, replace the single-document ownership check and retriever call with a multi-document loop:

1. **Ownership validation loop**: Iterate over `body.resolved_document_ids`. For each `doc_id`:
   - Check if the document exists globally: `vector_manager.vectorstore_dir.glob(f"*/{doc_id}")`. Raise HTTP 404 if not found.
   - Check if `vector_manager.vectorstore_dir / user_id / doc_id` exists. Raise HTTP 403 if not.

2. **Per-document hybrid retrieval loop**: Iterate over `body.resolved_document_ids`. For each `doc_id`:
   - Call `vector_manager.get_hybrid_retriever(user_id=user_id, document_id=doc_id, top_k=candidate_k)`.
   - Invoke `retriever.invoke(body.question)` and extend a `pooled_chunks` list with the results.

3. **Deduplication**: Deduplicate `pooled_chunks` by exact stripped text, preserving order of first occurrence:
   ```python
   seen = set()
   deduped_chunks = []
   for doc in pooled_chunks:
       key = doc.page_content.strip()
       if key not in seen:
           seen.add(key)
           deduped_chunks.append(doc)
   ```

4. **Reranking**: Pass `deduped_chunks` to `FlashrankRerank` compressor via `ContextualCompressionRetriever`. Since the compressor needs a retriever, pass the deduped docs directly via `compressor.compress_documents(deduped_chunks, body.question)` instead of invoking the retriever, then slice to `top_k`.

5. Remove the old single-document retriever call block. Pass `matching_chunks` from the reranked result to `qa_pipeline.generate_answer`.
</action>
<acceptance_criteria>
- Multi-document query pools results from each document retriever.
- Duplicate chunks across documents are removed before reranking.
- Single-document backward compatibility works (resolved_document_ids has one entry).
</acceptance_criteria>
</task>
