# Plan 20-01: Chat Session Management & Database Storage

## Goal

Expose REST CRUD endpoints for creating, listing, retrieving, and deleting chat sessions, and persist sessions and chronological messages history in the existing local SQLite database (`users.db`) using user-isolated query execution.

## Requirements Addressed

- **MEM-01**: User can create, list, retrieve, and delete chat sessions.
- **MEM-02**: Database storage for chat history using SQLite (with Cascading deletes and FK constraints enabled).

## Success Criteria

1. Database tables initialized on startup with proper schema and cascade deletes.
2. Endpoints `POST /sessions`, `GET /sessions` (paginated), `GET /sessions/{session_id}`, and `DELETE /sessions/{session_id}` fully functional with user-ownership and authentication.
3. All automated unit and integration tests run successfully.
