# Plan 17-01: API Quality & Developer Experience

## Goal

Harden the API surface with per-user rate limiting, paginated list endpoints, a standardized JSON error schema, and complete OpenAPI documentation metadata.

## Requirements Addressed

- **API-01**: Enforce configurable per-user rate limiting on `/upload` and `/query` (including `/query/stream`) endpoints.
- **API-02**: Support limit/offset pagination on `GET /documents` with response metadata.
- **API-03**: Standardize all error responses (4xx, 5xx) to follow the schema `{"detail": "...", "code": "...", "field": "..."}`.
- **API-04**: Fill in OpenAPI tags, summaries, and descriptions for all endpoints.

## Success Criteria

1. API returns HTTP 429 and `Retry-After` header when rate limits are exceeded.
2. Rate limits are configurable via env vars `RATE_LIMIT_QUERY` and `RATE_LIMIT_UPLOAD` (defaulting to `"30/minute"` and `"5/minute"` respectively).
3. `GET /documents` supports pagination using `limit` (default 10, max 100) and `offset` (default 0), and clamps out-of-bounds inputs.
4. `GET /documents` returns `{"total": N, "limit": L, "offset": O, "items": [...]}`.
5. All validation errors, authentication failures, missing resources, and server errors return the standard JSON error structure.
6. All endpoints in the API schema display complete OpenAPI metadata (tags, summaries, descriptions, response descriptions).
