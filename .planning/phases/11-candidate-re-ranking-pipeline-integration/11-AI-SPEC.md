## 1. System Classification

**System Type:** RAG (Retrieval-Augmented Generation with lexical-semantic fusion and cross-encoder re-ranking)

**Description:**
This system implements the retrieval re-ranking layer of the Document RAG REST API. It fetches a broader candidate list (top 10 results) from the ensemble hybrid retriever, re-ranks them locally on CPU using the FlashRank cross-encoder, and compresses the selection to the top 3 most relevant context chunks. These compressed chunks are then sent to the ChatGroq model to synthesize highly accurate, grounded Q&A responses with precise source citations.

**Critical Failure Modes:**
1. **Model Reload Latency:** Reloading the model on every query adds 2-5 seconds overhead, violating low-latency constraints.
2. **Memory Leaks / OOM:** Concurrent requests initiating duplicate model instances on CPU, leading to thread contention or out-of-memory crashes.
3. **Citation Metadata Loss:** Reranker modifying or dropping metadata (`source_filename`, `page_index`, `chunk_id`), which breaks the source citations logic.
4. **Tenant Context Leakage:** Cross-tenant leakage during the hybrid retrieval or re-ranking execution context.

## 1b. Domain Context

**Industry Vertical:** General Developer Tooling / Multi-tenant Document Q&A

**User Population:** API clients querying private uploaded documents via REST endpoints.

**Stakes Level:** Medium (Information lookup from private files)

**Output Consequence:** End-users read generated responses to make decisions. Incorrect retrieval leading to hallucinations or incorrect citations can mislead users.

### What Domain Experts Evaluate Against

* **Context Precision:** Are the re-ranked chunks actually relevant to the question? (Good: The top 3 chunks contain the exact answer. Bad: Irrelevant chunks push out relevant ones.)
* **Citation Accuracy:** Do the returned citations match the text snippets? (Good: Citation points to the correct page index and filename. Bad: Citations are mismatched or missing.)
* **System Latency:** Is the query response time acceptable? (Good: Under 1.5 seconds including LLM generation. Bad: Long delays due to model load or inference bottlenecks.)

### Known Failure Modes in This Domain

* **Lost in the Middle:** Lexical/semantic retrieval can return relevant chunks at lower positions (e.g. rank 8-10) which are ignored by the LLM if context is too wide. Reranking mitigates this by bringing them to ranks 1-3.
* **Metadata Stripping:** Some compression algorithms drop custom document metadata, making citations impossible to reconstruct.

### Regulatory / Compliance Context

* **Data Privacy:** 100% local operation for embeddings and re-ranking is mandatory (no external APIs like Cohere) to protect user data from third-party exposure.

### Domain Expert Roles for Evaluation

| Role | Responsibility |
|------|---------------|
| QA Engineer | Verify retrieval latency, memory stability under load, and correctness of citation mapping. |

## 2. Framework Decision

**Selected Framework:** FlashRank (via `flashrank` and `langchain-community`)

**Version:** `flashrank>=0.2.0`

**Rationale:**
FlashRank is an ultra-lightweight, high-performance Python library designed for local cross-encoder re-ranking. It runs extremely fast on CPU using ONNX Runtime, avoiding heavy PyTorch/Transformers dependencies and keeping resource usage minimal on host machines.

**Alternatives Considered:**

| Framework | Ruled Out Because |
|-----------|------------------|
| Cohere Rerank API | Requires network requests, API keys, and violates the requirement for 100% self-contained local persistence. |
| HuggingFace Cross-Encoder | Pulls in heavy PyTorch/Transformers dependencies, leading to massive memory footprint and slow CPU execution. |

**Vendor Lock-In Accepted:** No. FlashRank sits as a pluggable component in LangChain's document compression ecosystem.

## 3. Framework Quick Reference

### Installation
```bash

# pip install flashrank
```

### Core Imports
```python
from flashrank import Ranker
from langchain_community.document_compressors import FlashrankRerank
```

### Entry Point Pattern
```python
import os
import threading
from typing import Optional
from flashrank import Ranker
from langchain_community.document_compressors import FlashrankRerank
from langchain.retrievers import ContextualCompressionRetriever

class RerankManager:
    """Thread-safe singleton caching the FlashRank Ranker instance."""
    _instance: Optional[Ranker] = None
    _lock = threading.Lock()

    @classmethod
    def get_ranker(cls) -> Ranker:
        if cls._instance is None:
            with cls._lock:
                if cls._instance is None:
                    model_name = os.getenv("RERANK_MODEL", "ms-marco-MiniLM-L-12-v2")
                    # Ranker automatically downloads and caches the model on first initialization
                    cls._instance = Ranker(model_name=model_name)
        return cls._instance

# Dynamic instantiation of the compressor per request to allow configurable top_n (top_k)
ranker = RerankManager.get_ranker()
compressor = FlashrankRerank(client=ranker, top_n=3)

compression_retriever = ContextualCompressionRetriever(
    base_compressor=compressor,
    base_retriever=ensemble_retriever
)
```

### Key Abstractions

| Concept | What It Is | When You Use It |
|---------|-----------|-----------------|
| `Ranker` | Core FlashRank class that loads ONNX models and runs scoring. | Instantiated once and cached as a thread-safe singleton. |
| `FlashrankRerank` | LangChain compressor wrapper around the FlashRank Ranker. | Created dynamically per request to wrap retrieved documents. |
| `ContextualCompressionRetriever` | LangChain retriever wrapper that passes documents through a compressor. | Used to transparently re-rank base retriever results. |

### Common Pitfalls
1. **Import Order Pydantic Error:** As documented in LangChain community, Pydantic type validation can crash with `PydanticUserError` if `Ranker` is not imported *before* `FlashrankRerank`.
2. **Missing Metadata:** Ensure the compressor preserves the dictionary structure of metadata (specifically `page_index` and `source_filename`).
3. **ONNX Threading:** ONNX runtime can spawn multiple threads. The singleton `Ranker` is thread-safe, but concurrent calls will share the model instance.

### Recommended Project Structure
```
backend/
├── app/
│   ├── core/
│   │   ├── reranker.py       # RerankManager singleton
│   │   ├── vectorstore.py    # Retrieves candidate chunks using EnsembleRetriever
│   │   └── qa.py             # Generative QA pipeline
│   └── routes/
│       └── query.py          # FastAPI POST /query endpoint
```

## 4. Implementation Guidance

**Model Configuration:**
- Model name: `ms-marco-MiniLM-L-12-v2` (configured via `RERANK_MODEL` env, defaulting to this model).
- Cache directory: Default FlashRank cache directory (`~/.cache/flashrank/` or local fallback).

**Core Pattern:**
- Wrap `EnsembleRetriever` with a dynamically instantiated `FlashrankRerank` using `ContextualCompressionRetriever`.
- Execute `compression_retriever.invoke(query)` inside the query router.

**Tool Use:**
- None needed, 100% local.

**State Management:**
- Stateless per query, model state cached in-memory in the singleton.

**Context Window Strategy:**
- Retrieve 10 candidate documents (or `top_k * 3`, clamped between 10 and 25).
- Rerank and compress to `top_k` (default 3) documents. This keeps prompt context compact and highly relevant.

## 4b. AI Systems Best Practices

### Structured Outputs with Pydantic

Not directly applicable to FlashRank output, but Pydantic is used in `QueryRequest` (FastAPI router payload validation).

### Async-First Design
- Since FlashRank runs synchronously on CPU (ONNX inference), it should be invoked inside a FastAPI threadpool (using standard `def` route or run in `run_in_executor`) to prevent blocking the main event loop if query volume is high. Currently, the query endpoint is `async def query_document` and does synchronous retriever invocations, which FastAPI automatically executes in a thread pool.

### Prompt Engineering Discipline
- FlashRank output is passed to `QAPipeline.generate_answer`. The prompt template requires strictly grounded context. Reranking ensures the prompt context matches the most relevant chunks.

### Cost and Latency Budget
- Cost: $0 (local CPU inference).
- Latency budget: <100ms for FlashRank re-ranking step.

## 5. Evaluation Strategy

### Dimensions

| Dimension | Rubric (Pass/Fail or 1-5) | Measurement Approach | Priority |
|-----------|--------------------------|---------------------|----------|
| Singleton Caching | Pass: Subsequent model access takes <1ms. Fail: Reloading model takes >1s. | Integration Test asserting execution time of second retrieval. | Critical |
| Reranking Quality | Pass: Final retrieved chunks include the most relevant answer context. | Integration test asserting specific text content appears in top 3 after re-ranking. | High |
| Citation Alignment | Pass: Citations match the final re-ranked documents. | API test validating `/query` payload citations structure. | Critical |

### Eval Tooling

**Primary Tool:** Unit and Integration tests using pytest.

**CI/CD Integration:** Runs on Git commit/PR verification pipeline.

### Reference Dataset

**Size:** 5 test documents with target queries.

**Composition:**
- Verification queries with answers placed at different chunk ranks (e.g. rank 5 or 8) to prove that re-ranking successfully elevates relevant context to the top 3.
