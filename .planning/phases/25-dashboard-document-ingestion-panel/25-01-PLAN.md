# Plan 25-01: Dashboard & Document Ingestion Panel

## Goal

Create the landing view (`/`), document drag-and-drop UploadModal, and real-time status polling for uploaded documents, enabling users to manage their vector documents securely.

## Requirements Addressed

- **FE-DOC-01**: Dashboard landing screen with summary statistics and a list of the user's uploaded documents.
- **FE-DOC-02**: Drag-and-drop document upload interface with client validation (max 50MB, PDF/DOCX only) and loading states.
- **FE-DOC-03**: Real-time status polling hook that queries `/documents` every 3 seconds to update document processing states (processing, complete, error), stopping once all documents reach terminal states.
- **FE-DOC-04**: Ability to delete documents, triggering backend removal and refreshing local state.

## Success Criteria

1. Dashboard landing page `/` renders stats cards (Total Documents, Total Chunks, Ingestion Status) and document table.
2. Drag-and-drop UploadModal opens on button click, validates file constraints (PDF/DOCX, <= 50MB), and starts upload tracking.
3. Active uploads are saved in `localStorage` under `document_rag_active_jobs` to survive page reloads and polled every 3 seconds.
4. Clicking document "Delete" prompts for confirmation, hits backend DELETE `/documents/{uuid}`, and refreshes lists.
5. All client-side Vitest unit tests pass.

---

## Threat Model

### Threats Identified

1. **Malicious File Uploads (RCE/Shells)**: Uploading arbitrary scripts disguised as documents.
   - Mitigation: Validate file types on the client (accepting only `.pdf`, `.docx`) and verify files are within the 50MB limit before sending. The backend also enforces extension checks.
2. **Denial of Service (DoS)**: Flooding upload routes with large numbers of concurrent uploads.
   - Mitigation: Expose backend Rate Limiting (enforced by the backend `RATE_LIMIT_UPLOAD` SlowAPI configuration).
3. **Data Loss (Accidental Deletion)**: Users clicking delete by accident.
   - Mitigation: Enforce explicit browser `confirm()` or modal confirm dialogue before issuing the backend DELETE call.
