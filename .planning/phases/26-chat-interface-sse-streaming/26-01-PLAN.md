# Plan 26-01: Chat Interface & SSE Streaming

## Goal

Create a high-fidelity conversational chat panel at `/chat` displaying active chat histories, supporting dynamic multi-select context, streaming token responses chunk-by-chunk using readable streams with smart auto-scroll, and rendering hover-active citation tooltips.

## Requirements Addressed

- **FE-CHAT-01**: Sidebar listing active user chat sessions; selecting a session loads its chronological message history.
- **FE-CHAT-02**: "New Chat" conditional modal flows:
  - If no documents are uploaded, automatically open the file upload modal.
  - If documents exist, open a modal listing files for multi-select (default-selecting the first document) to define the chat context.
  - Chat access is blocked if no documents are selected or exist.
- **FE-CHAT-03**: Main chat scrollable viewport rendering user and assistant message turns cleanly.
- **FE-CHAT-04**: Token-by-token SSE streaming response rendering with smooth auto-scroll to the bottom of the chat interface.
- **FE-CHAT-05**: Dynamic chat session title updates in the sidebar list when the backend generates the title on the first question turn.
- **FE-CHAT-06**: Interactive citation tooltips next to assistant grounding statements, showing the document name and matching pages on hover.

## Success Criteria

1. Navigating to `/chat` renders the two-panel grid layout (session history sidebar + conversation container).
2. Starting a new chat checks the document registry and presents a select modal or triggers file ingestion if empty.
3. Chat queries stream responses dynamically from POST `/query/stream`, showing a cursor indicator at the end of the text.
4. Autoscrolling triggers on incoming stream text only if the viewport is within 80px of the bottom.
5. First message completes triggers a list refresh to load the generated title from FastAPI.
6. Hovering citation tags (`[1]`) opens floating overlays rendering the filename, page index, and context text snippet.

---

## Threat Model

### Threats Identified

1. **Broken Routing Access Controls**: Bypassing path protection to access `/chat` directly without a session cookie.
   - Mitigation: Ensure Next.js `middleware.ts` runs the routing verification function exported in `proxy.ts`.
2. **Denial of Service (DoS)**: Rapid-fire chat query submissions.
   - Mitigation: Enforce rate limit warnings on the backend and client-side submit button disabled states during active generation.
