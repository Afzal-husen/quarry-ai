# Plan 27-01: LLM Response & Retrieval Enhancements

## Goal

Refine the LLM prompts to support structured markdown output, strict inline citations, and general-knowledge fallback with disclaimers (exemption for greetings). Implement multi-query expansion and Reciprocal Rank Fusion (RRF) retrieval.

## Requirements Addressed

- **REQ-RAG-01 (Strict Inline Citations)**: Explicit inline citations (e.g., `[1]`, `[2]`) in LLM response text pointing to context indices.
- **REQ-RAG-02 (Detailed Formatting Rules)**: Clean Markdown output formats (bullet points, headers, lists, code blocks).
- **REQ-RAG-03 (Groq Model Selection)**: Configurable Groq model override using the `GROQ_MODEL` environment variable.
- **REQ-RAG-04 (Query Rewriter/Expansion Step)**: Rewriter step generating 3 alternative queries.
- **REQ-RAG-05 (Multi-Query Retrieval & Fusion)**: Pool query variations, merge using RRF, and re-rank via FlashRank.
- **REQ-RAG-06 (General Knowledge Fallback & Greetings Exception)**: Disclaimer suffix/prefix fallback on empty/missing contexts; direct natural greeting answers without disclaimers.

## Success Criteria

1. The LLM response includes inline citation markings (`[1]`, `[2]`) in both sync and stream modes, falls back to general-knowledge answers with standard disclaimers if no relevant document context is found, and responds to generic greetings naturally in a helpful tone without a disclaimer.
2. Alternative queries are correctly generated using ChatGroq.
3. Multi-query search retrieves documents for all queries, fuses them using Reciprocal Rank Fusion (RRF), and re-ranks using FlashRank.
4. Unit and E2E integration tests are updated to assert LLM query expansions and pass cleanly.

---

## Threat Model

### Threats Identified

1. **LLM Hallucinations on Missing Context**: The LLM may hallucinate and attribute fake facts to documents when document search returns empty or irrelevant results.
   - Mitigation: Enforce REQ-RAG-06 with a strict fallback instruction stating that if information is missing from documents, it must answer with its general knowledge and append the required disclaimer.
2. **Resource Exhaustion (Rate Limits on Groq)**: Generating query expansions (which adds one LLM call per search request) might cause users to hit Groq rate limits.
   - Mitigation: Keep model temperature low, rate limit `/query` endpoints via slowapi, and use the fast `llama-3.1-8b-instant` or similar model for query expansions.

<type>execute</type>
<description>Integrate RRF multi-query search in query routes</description>
<read_first>
  - backend/app/routes/query.py
</read_first>
<action>
Modify `backend/app/routes/query.py` (`query_document` and `query_document_stream`):
1. Call `qa_pipeline.generate_alternative_queries(rewritten_question)` to fetch 3 queries.
2. Create the full query set: `all_queries = [rewritten_question] + expanded_queries`.
3. For each query in the set:
   - Retrieve documents using `vector_manager.get_hybrid_retriever()`.
   - Calculate RRF score contribution for each document:
     $$RRF(d) = \sum_{q} \frac{1}{60 + \text{rank}(d, q)}$$
     Where `rank` is `index + 1` of the document chunk in that query's retrieval list.
   - Accumulate scores in a dict keyed by unique chunk identifier: `(doc.page_content.strip(), doc.metadata.get("chunk_id", ""))`.
4. Sort unique documents by their accumulated RRF score descending.
5. Slice to top candidate list (size `candidate_k`) and pass to FlashRank for final re-ranking down to `top_k`.
</action>
<acceptance_criteria>
- RRF scoring calculations are applied correctly.
- Deduplication and re-ranking execute successfully.
</acceptance_criteria>
</task>
