# Plan 23-01: Next.js Bootstrap & API Client Layer

## Goal

Set up the Next.js App Router application in the `/frontend` directory with TypeScript and Tailwind CSS, and implement a custom Fetch-based API client with structured error parsing and automatic JWT insertion.

## Requirements Addressed

- **FE-CORE-01**: Next.js App Router project initialized with TypeScript and Tailwind CSS under a `/frontend` directory.
- **FE-CORE-02**: Centrally configured API client wrapper (`api-client.ts`) that manages API base mapping, automatically injects JWT Bearer header, and redirects users to `/login` upon receiving `401 Unauthorized` responses.

## Success Criteria

1. Next.js App Router workspace is successfully initialized under `/frontend` with TypeScript, Tailwind CSS, and `pnpm`.
2. Tailwind CSS loads standard styling rules and compiles successfully.
3. The `api-client.ts` custom fetch wrapper is implemented, appends `Authorization: Bearer <token>` headers if a token is present in `localStorage`, and throws a custom `APIError` parsing the backend validation messages.
4. Non-authenticated client requests returning `401 Unauthorized` are caught and trigger redirects to `/login`.
5. Frontend compiles cleanly (`pnpm run build`) without TypeScript or ESLint errors.

---

## Threat Model

### Threats Identified

1. **Local Access Token Leaks (XSS)**: If the app is compromised via XSS, storing JWTs in `localStorage` exposes them to theft.
   - Mitigation: Leverage React's automatic escaping for all text nodes. Lock down script sources when deploying.
2. **CORS Origins Exposure**: Improper origin validation could allow unauthorized domains to call backend endpoints.
   - Mitigation: In subsequent steps, restrict backend FastAPI CORS allowed origins specifically to `http://localhost:3000` (the Next.js development server origin).

  - .planning/phases/23-next-js-bootstrap-api-client-layer/23-CONTEXT.md
</read_first>
<action>
Create `frontend/src/lib/api-client.ts` containing:
1. Custom class `APIError` extending `Error`, storing `status` (HTTP status code) and `detail` (raw detail or structured backend validation errors).
2. Base URL mapping pointing to `process.env.NEXT_PUBLIC_API_URL` falling back to `http://localhost:8000`.
3. Standard client wrappers (`apiGet`, `apiPost`, `apiDelete`) that intercept request headers to fetch and inject the `localStorage` access token.
4. Response check logic that throws `APIError` on status >= 400 and wipes credentials/redirects to `/login` on status 401.
</action>
